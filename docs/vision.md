# Scroll Motion Atlas 제품 방향

> **결론:** 이 프로젝트는 스크롤 인터랙션을 재사용 가능한 코드로 제공하는 패턴 프레임워크와, 그 패턴을 직접 체험하고 학습하는 내부 웹사이트를 함께 만든다.

## 문제

제품 홍보 페이지의 움직임은 인상적이지만, 어떤 스크롤 경계에서 무엇이 움직이고 프레임워크별로 어떻게 재현하는지 알기 어렵다. 완성 사이트 모음은 레퍼런스가 되지만 재사용 가능한 구현 지식으로 이어지지 않는다.

## 두 제품 축

| 축 | 대상 | 제공 가치 | 완료 기준 |
|---|---|---|---|
| Pattern Framework | 개발자 | React·Vue·Plain JS에서 재사용하는 패턴과 공통 계산 로직 | 한 패턴이 세 환경에서 같은 경계와 되감기를 보장 |
| Pattern Experience Site | 기획자·디자이너·개발자 | 실제 조작 가능한 데모, 원리, 적용 조건 | 데모와 문서가 프레임워크 구현을 직접 사용 |

## 제품 원칙

1. **스크롤은 하나다.** 사용자에게 내부 스크롤바나 중첩 스크롤을 강요하지 않는다.
2. **되감겨야 한다.** 모든 scroll-driven 패턴은 역스크롤 때 현재 스크롤 위치에 맞는 상태로 돌아간다.
3. **기법보다 결과를 먼저 분류한다.** 사용자는 `내부 장면 이동`, `이미지 리빌`처럼 보이는 효과로 탐색한다.
4. **프레임워크는 구현체다.** 패턴의 경계·진행률·옵션은 공통 의미를 가지며 React·Vue·Plain JS 코드는 이를 따르는 어댑터다.
5. **데모는 문서가 아니라 제품이다.** 체험 사이트는 실제 프레임워크 코드를 실행한다.

## MVP

- 패턴 4개: 내부 장면 이동, 고정 장면 전환, 이미지 리빌, 레이어 패럴랙스
- 각 패턴의 React·Vue·Plain JS 구현
- 패턴 인덱스와 상세 체험 페이지
- 시작·종료 경계, 진행률 공식, 성능·모바일·접근성 안내

## 현재 결정

- `내부 장면 이동`을 첫 번째 기준 구현으로 삼는다. `src/patterns/inner-scene-scroll.js`
- CSS `overflow: hidden`으로 장면 밖 콘텐츠만 가리고, 움직임은 document scroll 진행률에서 만든 `transform`으로 제어한다. `src/patterns/inner-scene-scroll.js`
- 새 패턴이 3개 이상 생기기 전에는 모노레포나 패키지 분리를 도입하지 않는다. 현재는 탐색 비용보다 구조 비용이 크다.
